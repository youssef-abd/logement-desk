# logement-desk, plan 3: volume, quality, design

**Goal:** many more listings (hundreds to ~1,500), ranked by quality signals, in a desk built for browsing and for researching where to live. Alerts are out of scope (later). Matching criteria stay variables in the private profile.

**Measured 2026-11-21:** Leboncoin has ~309 matching listings (9 pages of 35; page 12 is empty); Bien'ici reports ~8,940 (size up to 200 per request, `from` works to ~2,000+, 5,000 errors; many duplicates and multi-unit residences; some ads have `publicationDate` 1970-01-01); `lbc` and Bien'ici both paginate.

**Decisions:** two polling depths: *light* every 10 min (page 1, freshness) and *deep* hourly (all pages, coverage); a blocked page after page 1 returns the pages already fetched; payload capped at 1,500 newest with identical units collapsed; "fresh" for alerts means first seen in the last 90 minutes (a deep sweep must not flood alerts); computed fields (`eur_m2`, area medians, cheap/too-cheap tags) live in the export, not in git state.

## Tasks (each: tests first, review where noted)

1. **Deep pagination (Python, reviewed).** Adapters read `profile.get("deep")`. Bien'ici: deep = size 200, pages up to `sources.bienici.deep_pages` (default 6), stop when a page returns fewer than `size`; light unchanged. Leboncoin: deep = pages 1..`deep_pages` (default 9), 1.5 s sleep between pages, stop on a short page. If a page after the first raises `Blocked`, keep the pages already fetched. `published_at` starting `1970` becomes `None`. `run(profile, state, now, deep=False)` copies the profile with `deep`; CLI flag `--deep`; `run.yml` gets a boolean input `deep`; the Worker passes `deep: "true"` on the hourly tick (`isDue`) and `"false"` otherwise.
2. **Payload scale and fresh window (Python + JS, reviewed).** Export cap 400 -> 1500 and photos capped at 3 per listing; `cleanPayload` cap 1500; ingest body cap 2 MB -> 6 MB; ingest counts a listing as fresh only if `first_seen` is within 90 minutes of `now` (test: a deep sweep of old listings sends nothing).
3. **Quality fields (Python export + JS validation, reviewed).** Per listing: `eur_m2`, `posted` (valid `published_at` else `first_seen`), `similar` (identical source, poster, rent, surface, postal code collapsed to the newest, count of the others). Payload `areas`: per postal code `{n, median_eur_m2}` from active listings. Tags added in the export only: `cheap-for-area` (eur_m2 <= 75% of the area median, area n >= 8) and `too-cheap` (<= 50%: possible scam). `cleanPayload` accepts the new fields and `areas`.
4. **Desk upgrade (JS, reviewed for XSS/CSP).** Sort (newest, price, EUR/m2, size); density toggle (cards or compact); area chips with counts and median EUR/m2; paging (60, then "load more"); "new since your last visit" marker (localStorage); stage `saved` plus a Saved tab; photo carousel with arrows and keys; "posted X ago" and "+N similar"; "Copy message" (French template; the user's Visale number is stored locally in Settings). No inline scripts or styles, text only through the DOM.
5. **Config and measurement (controller).** Private profile: `max_rent_cc` 600, `near_miss_margin` 100, kinds studio/t1/t2, area = Lyon 1-9 plus Villeurbanne, Caluire, Bron, Venissieux, Oullins, Saint-Fons, Ecully (postal codes and Bien'ici zone ids), Leboncoin radius 9,000 m. Run a deep sweep on Actions; report counts per source, block rate and desk load time.
6. **Later (not in this plan):** arrondissement SVG map filter, ParuVendu and La Carte des Colocs (need list URLs and kinds), alerts, price-drop tracking.
